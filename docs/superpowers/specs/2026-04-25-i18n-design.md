# i18n (en + ja) 設計書

## 目的

PDFPW UI を英語/日本語に対応する。現状 UI は英日が混在しており (例: ヘッダ系英語、Library / 一部 presenter ボタン日本語)、文字列が今後増える前に基盤を入れる。SEO 対応として URL に locale prefix (`/en/` `/ja/`) を持ち、ランディングは locale 別 HTML を pre-render する。

関連 issue: [#10](https://github.com/pdfpw/pdfpw.github.io/issues/10)

## スコープ

- 言語: **英語 (en) + 日本語 (ja)** の 2 言語のみ
- 検出順: URL の `$locale` segment > `localStorage("pdfpw:locale")` > `navigator.language` > `en` (デフォルト)
- 切替 UI: ヘッダー右側の `EN | JA` トグルボタン
- 移行範囲: **既存 UI 全文字列** (~195 件)。フレームワーク導入と全コンポーネント置換を 1 PR で完了
- pre-render: ランディング (`/en/` `/ja/`) のみ locale 固定の `<head>` を持つ HTML を生成。本文は React runtime レンダリング
- 翻訳対象外: PDF メタデータ、`.pdfpc` ノート、ファイル名等のユーザー入力

## アーキテクチャ概要

| レイヤ | 採用技術 | 役割 |
|---|---|---|
| メッセージカタログ | `@inlang/paraglide-js` v2 + Vite plugin | コンパイル時 tree-shake、型安全な `m.foo()` 関数を生成 |
| ロケール source of truth | URL の `$locale` セグメント | 切替 = navigation。URL リロードで状態復元 |
| ロケール検出 (ルート `/` のみ) | localStorage > navigator.language | 直アクセス時の初回リダイレクト先決定 |
| ルーティング | TanStack Router (file-based) を `$locale` 配下に再構成 | `/$locale/(main)` `/$locale/presentation` |
| ランディング SEO | Vite plugin で `en/index.html` `ja/index.html` を生成 | `<html lang>` `<title>` `<meta description>` `og:locale` `hreflang` をビルド時固定 |
| 日付・数値フォーマット | `Intl.DateTimeFormat` / `Intl.NumberFormat` を薄ラップ | `getLocale()` で現在 locale を読む |

## ルーティング構造

```
src/routes/
  __root.tsx                               # 既存 (変更最小)
  index.tsx                                # NEW: locale 検出 → /en/ or /ja/ へ Navigate
  $locale/
    route.tsx                              # NEW: locale 検証 + paraglide.setLocale(params.locale)
    (main)/
      route.tsx                            # 旧 src/routes/(main)/route.tsx
      index.tsx                            # 旧 src/routes/(main)/index.tsx
      licenses.tsx                         # 旧 src/routes/(main)/licenses.tsx
      presenter.tsx                        # 旧 src/routes/(main)/presenter.tsx
      -index/                              # 旧 -index/ ディレクトリ移動
      -presenter/                          # 旧 -presenter/ ディレクトリ移動
    presentation/
      route.tsx                            # 旧 src/routes/presentation/route.tsx
      $fileName.$pairId.tsx                # 旧ファイル群
      -hooks/                              # 旧フック
      -Menu.tsx
      -SlideStage.tsx
      index.tsx
  -hooks/                                  # ルート共通フック (変更なし、locale 配下に置かない)
```

`$locale/route.tsx` の責務:
- `params.locale` を `["en", "ja"]` で検証。invalid なら `redirect({ to: "/en" + restOfPath })`
- mount 時に `setLocale(params.locale)` を呼んで paraglide runtime を URL と同期

`/` ルート (`src/routes/index.tsx`):
- 検出ロジック実行 → `<Navigate to="/$locale" params={{ locale }} replace />`

### TanStack Router 自動生成ファイル

`src/routeTree.gen.ts` は plugin が自動再生成する。手動編集不要。差分は大きいが 1 コミット内に収める。

### キー命名規則

- snake_case で `<area>_<element>_<variant>`
- area: `app, header, hero, library, mode, presenter, presentation, kb, error, dialog, license, toast, locale, meta`
- 例:
  - `header_help_aria` "Keyboard shortcuts"
  - `hero_headline` "Precise by default."
  - `library_history_toggle` "Save history"
  - `kb_slide_next_label` "Next slide"
  - `kb_slide_next_hint` "Advance to the next slide or overlay"
  - `error_pdf_open_failed` "Failed to open the PDF file"
  - `meta_title` (HTML `<title>` 用) "PDFPW — Precise PDF presenter"
  - `meta_description`

### KEYBINDING_CATALOG の改修

現状:
```ts
"slide.next": { ..., label: "Next slide", hint: "Advance to the next slide" }
```

改修後 (`src/lib/keybindings.ts`):
```ts
import { kb_slide_next_label, kb_slide_next_hint, ... } from "#src/paraglide/messages.js";

export interface ActionDefinition {
  category: Category;
  scope: Scope;
  bindings: readonly Binding[];
  label: () => string;            // 関数参照に変更
  hint?: () => string;            // 関数参照に変更

"slide.next": { ..., label: kb_slide_next_label, hint: kb_slide_next_hint }
```

UI 側 (`KeybindingHelpDialog.tsx`) で `def.label()` `def.hint?.()` を呼ぶ。

### ICU 例 (pluralization)

`messages/en.json`:
```json
{
  "library_count": "{count, plural, one {# file} other {# files}} · recent first"
}
```

`messages/ja.json`:
```json
{
  "library_count": "{count} 件のファイル · 新しい順"
}
```

(日本語は plural 形式の差がないため平文)

### JSX 埋め込み文字列

paraglide はメッセージ内 JSX を直接サポートしないため、**メッセージを分割** して JSX で連結する。

例: `KeybindingHintToast` "Press ? for keyboard shortcuts"
```tsx
<span>{m.toast_hint_prefix()} <Kbd>?</Kbd> {m.toast_hint_suffix()}</span>
```

`messages/en.json`:
```json
{
  "toast_hint_prefix": "Press",
  "toast_hint_suffix": "for keyboard shortcuts"
}
```

該当箇所は概算 4-5 件 (`KeybindingHelpDialog` フッタ "Press ? again or Esc to close"、`KeybindingHintToast`、ランディング cta hint 等)。

## ロケール検出と切替

### 検出順 (ルート `/` 直アクセス時のみ)

1. `localStorage.getItem("pdfpw:locale")` が `en` か `ja` ならそれ
2. `navigator.language.startsWith("ja")` なら `ja`
3. それ以外は `en`

### 切替動作 (`LocaleSwitcher`)

- ヘッダー右側 (`?` ヘルプボタンの**左**) に配置
- 表示: `EN | JA` の 2 ボタン (segment 風)。現在 locale は `aria-pressed="true"` 表示
- クリック時:
  1. 現在の `pathname` から locale prefix を新 locale に置換 (例: `/ja/presenter` → `/en/presenter`)
  2. `useNavigate({ to: newPath, replace: true })`
  3. `localStorage.setItem("pdfpw:locale", newLocale)` (ルート `/` 直アクセス時の優先選択を更新)
- aria-label: `m.locale_switcher_aria()` "Switch language"

### 配置箇所

| 画面 | 切替 UI |
|---|---|
| ランディング `/en/` `/ja/` | あり (Header) |
| Presenter | あり (Header) |
| Presentation 単独ウィンドウ | **なし** (発表中の誤操作防止) |

### Presenter → Presentation ウィンドウ起動時

presenter 内で `window.open(url)` する箇所 (`src/routes/(main)/presenter.tsx` 周辺) で URL 構築時に現在 locale を含める:
```ts
const locale = useParams({ from: "/$locale" }).locale;
window.open(`${origin}/${locale}/presentation/${fileName}/${pairId}`);
```

開かれた presentation ウィンドウは独立に URL から locale を読み取るので BroadcastChannel 同期不要。

## ビルド時 multi-HTML

### Vite plugin (`vite.config.ts` 内に inline)

`localeHtmlPlugin` を実装:

1. `buildStart`: テンプレート `index.template.html` を読み込み、locale ごとにトークン置換した HTML を `dist/{locale}/index.html` に書き出す予定の入力として登録
2. `transformIndexHtml`: ルート `index.html` (検出 redirect ページ) の `<title>` `<description>` をフォールバック (en) で埋める
3. paraglide compile output (`src/paraglide/messages.js`) から `m.meta_title()` `m.meta_description()` を import して各 locale で評価
4. `closeBundle`: `dist/index.html` を `dist/404.html` にコピー (SPA fallback)

### `index.template.html`

```html
<!doctype html>
<html lang="%LANG%" class="dark">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <link rel="icon" href="/favicon.ico" />
    <meta name="theme-color" content="#000000" />
    <title>%TITLE%</title>
    <meta name="description" content="%DESCRIPTION%" />
    <link rel="canonical" href="https://pdfpw.github.io/%LOCALE%/" />
    <link rel="alternate" hreflang="en" href="https://pdfpw.github.io/en/" />
    <link rel="alternate" hreflang="ja" href="https://pdfpw.github.io/ja/" />
    <link rel="alternate" hreflang="x-default" href="https://pdfpw.github.io/en/" />
    <meta property="og:locale" content="%OG_LOCALE%" />
    <meta property="og:title" content="%TITLE%" />
    <meta property="og:description" content="%DESCRIPTION%" />
    <meta property="og:type" content="website" />
    <meta property="og:url" content="https://pdfpw.github.io/%LOCALE%/" />
    <link rel="apple-touch-icon" href="/logo192.png" />
    <script>
      /* テーマ復元スクリプト (既存と同じ) */
    </script>
  </head>
  <body>
    <div id="app"></div>
    <script type="module" src="/src/main.tsx"></script>
  </body>
</html>
```

トークン展開:
- `%LANG%` → `en` / `ja`
- `%LOCALE%` → `en` / `ja`
- `%TITLE%` → en: "PDFPW — Precise PDF presenter" / ja: "PDFPW — 精密設計の PDF プレゼンタ"
- `%DESCRIPTION%` → 各 locale の説明
- `%OG_LOCALE%` → `en_US` / `ja_JP`

### ルート `index.html` (検出 redirect)

```html
<!doctype html>
<html lang="en" class="dark">
  <head>
    <meta charset="UTF-8" />
    <link rel="canonical" href="https://pdfpw.github.io/en/" />
    <title>PDFPW</title>
    <script>
      (() => {
        try {
          const stored = localStorage.getItem("pdfpw:locale");
          let locale = stored === "ja" || stored === "en" ? stored : null;
          if (!locale) locale = navigator.language.startsWith("ja") ? "ja" : "en";
          if (location.pathname === "/" || location.pathname === "") {
            location.replace("/" + locale + "/" + location.search + location.hash);
          }
        } catch (_) { /* SPA が <Navigate> でフォールバックリダイレクト */ }
      })();
    </script>
  </head>
  <body>
    <div id="app"></div>
    <script type="module" src="/src/main.tsx"></script>
  </body>
</html>
```

### `dist` 出力

```
dist/
  index.html        (root, redirect)
  404.html          (= index.html copy, SPA fallback for deep links)
  en/index.html     (localized head + SPA bootstrap)

  ...
```

## 日付・数値フォーマット

`src/lib/format.ts` (新規):
```ts
import { getLocale } from "#src/paraglide/runtime.js";

export function formatDateTime(date: Date | number, options?: Intl.DateTimeFormatOptions): string {
  return new Intl.DateTimeFormat(getLocale(), options).format(date);
}

export function formatNumber(n: number, options?: Intl.NumberFormatOptions): string {
  return new Intl.NumberFormat(getLocale(), options).format(n);
}
```

既存置換対象:
- `src/routes/(main)/-index/LibrarySectionData.tsx` (~1 箇所): `new Date(item.lastOpened).toLocaleString("ja-JP")` → `formatDateTime(item.lastOpened, { dateStyle: "medium", timeStyle: "short" })`
- スライド番号 (`X / Y`) は数字のままで OK (locale 影響なし)

### 2. `format.ts` (`src/lib/format.test.ts`)

- `setLocale("en")` 後と `setLocale("ja")` 後で `formatDateTime` の出力が異なること
- `formatNumber(1234)` が locale で適切に区切り処理されること

### 3. `LocaleSwitcher` (`src/components/LocaleSwitcher.test.tsx`)

- クリックで `useNavigate` が `{ to: <反対 locale prefix の path>, replace: true }` で呼ばれる
- `localStorage` が更新される
- 現在 locale ボタンは `aria-pressed="true"`

### 4. ルート redirect (`src/routes/index.test.tsx`)

- `localStorage = "ja"` で `/ja` にリダイレクト
- `localStorage = null`, `navigator.language = "ja-JP"` で `/ja` にリダイレクト
- `localStorage = "fr"` (invalid), `navigator.language = "en-US"` で `/en`
- `localStorage = "en"`, `navigator.language = "ja-JP"` で `/en` (localStorage 優先)

### 5. `$locale` route guard

- `/fr/` 等 invalid locale で `/en/` へ redirect
- `/en/`, `/ja/` は通る

### 6. ビルド出力検証 (手動チェック項目、自動化なし)

- `pnpm build` 後 `dist/index.html`, `dist/en/index.html`, `dist/ja/index.html`, `dist/404.html` が存在
- 各 locale HTML の `<html lang>` `<title>` `<meta description>` `og:locale` が適切
- `404.html` は ルート `index.html` と同一内容

`keybindings.test.ts` 等は locale 非依存。ただし `KEYBINDING_CATALOG` 型変更 (label が string → 関数) に伴い、テスト内の参照箇所を更新。

## 既知の制約・リスク

- **paraglide v2 のメッセージ関数は同期的だが locale 切替後の re-render は React 側責務**: URL ナビゲートで TanStack Router が render するので問題なし。万が一切替直後に古い文字列が残るケースがあれば `key={locale}` で root re-mount を検討。
- **Vite plugin による HTML 生成のタイミング**: paraglide が `src/paraglide/` を生成する `buildStart` フェーズで `localeHtmlPlugin` が import するため、plugin 順序に依存。paraglide plugin を先に配置し、`buildStart` の `order: "post"` を付ける。
- **GH Pages の deep link 404**: `/en/presenter` 等は HTTP 404 ステータスを返すが、`404.html` SPA fallback でユーザー体験は正常。SEO 上のインデックス対象は `/en/` `/ja/` のみで設計上問題なし。
- **既存ブックマーク (`/`) は引き続き動作**: 検出後 `/en/` か `/ja/` に replace するため壊れない。
- **`base: "/"` のままで問題なし**: GH Pages 配下 (`pdfpw.github.io`) は org page で配信パスがルートのため。
